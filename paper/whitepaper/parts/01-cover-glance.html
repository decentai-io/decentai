DecentAI
White paper · November 2026

AI agents you can let act, because the model decides nothing.

How DecentAI lets an assistant do real work on your mail, files and systems, on machines you run, while every action is checked, the costly ones wait for you, and the code that does the work runs in a jail with one way out.

Ahmed Dirir · DecentAI · ahmed@decentai.io · decentai.io
At a glance

One decision, kept everywhere

AI assistants do things: they send mail, change records, browse the web, run programs. The models behind them are capable and can't be trusted, and the tools they use are written by strangers. DecentAI is a platform an organization runs on its own machines, which lets an assistant do real work anyway. It rests on one decision.

The model proposes. The platform disposes.
01

Nothing happens on the model's word

Every proposal passes one gate: declared, granted, valid, within the chat's trust. No check reads what the model wrote around it.

02

What costs more waits for you

A call above the chat's trust stops and shows you a card with its exact inputs. Your yes covers that call and no other.

03

An agent holds nothing

An agent is a program with no standing credentials. Every ask goes through the runtime, held to what its function declared.

04

Strangers' code runs in a jail

Each run has a jail of its own, a user of its own, and one way out, to the hosts its manifest declared.

05

What you approve is what runs

A person reviews one exact release, which is pinned by digest. Reading a source runs nothing, and an update is a fresh review.

06

What you see really happened

Tables beside the assistant's words come from stored results of real calls, and every call leaves a line on an append-only trail.

The design in five lines

PartIts one jobWhat it never does
API serverthe data API, with access controlrun a model or an agent
Runtimeall the agentic work, holding nothing durablereach the database, or load agent code
Sandboxrun untrusted programs in jailsknow what an agent is
Egressbe the runs' one way out, inside the runtimeread encrypted traffic
Issuercertify every nodeknow what a node does

Each is a node with a certificate, and they talk over HTTPS with mutual TLS on port 8004. Each has a clean interface, so someone else could write their own.

How to read this paper

It is written for two readers. To get the argument, read each chapter's opening and the short statements with a green bar. To check us, read what sits under a Mechanism bar: the exact mechanism, and on the right the files that do it. Chapters 17 to 19 say what is at stake if a part is taken over, what is tested, and what isn't proven.
