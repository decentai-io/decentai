What the tests do not show
  • How well a real model resists a cleverly written email. No test asks a real model anything.
  • The whole call filter, live. The live probe tries two of its calls. The rest is a list in a fixed file, read here and not attacked.
  • The memory rule. No test fills a sandbox and watches it end the largest run.
  • A run attacking a run. No live test has one run reach for another's files, processes or sockets. That rests on the jail's user and namespaces, and the probe above.
  • Speed and behaviour at large scale. None of these suites measures them.
  • A flaw in the Linux kernel, which is a way past every layer, and which no test can rule out.
19 · What it does not do

The limits, in one place

Every gap we know of, for a reader deciding whether to trust the rest. Some are trade-offs made on purpose, some aren't done yet, and some come from what the platform runs on.

The sandbox

LimitWhat it means
No memory cgroup per runA container can't write its own cgroup, so a run has no memory limit of its own. The container's limit holds them all, and the sandbox ends the largest at 90%. Compose sets no limit unless SANDBOX_MEMORY is given, and with none the sandbox ends no run for memory. Between its looks, once a second, a run can reach the limit first, and the kernel ends a process of its choosing
No processor or time limit on a runA run may hold the container's processors for as long as it lives. A function has a timeout. The run under it doesn't
Abstract unix sockets are sharedThey belong to the container's network, so a run could reach one another run listens on. Nothing of the platform's listens on one
Runs share a kernelnsjail is a process jail, not a virtual machine. A kernel flaw is a way past all of it. Where that is too much to share, the separation is another sandbox, set aside by scope
It needs a stronger container than Docker's defaultUser namespaces, mounting and an unmasked /proc are given to the container, and the jail's own filter is what withholds them from runs. On AppArmor hosts the operator adds the profile: Compose doesn't name it

Agents and the way out

LimitWhat it means
A level is the publisher's wordThe platform checks it is 0 to 3, and takes the publisher's word for what a function does. A level 0 that sends mail is caught by a reviewer, or not at all
Nothing reads the programA digest pins bytes, not behaviour. Nothing scans an agent, and catalogs carry no publisher's signature: the digest comes from the catalog that was reviewed. Review is the control
An approved agent can misuse what it is lentIt can use a mailbox against the hosts it declared, and keep a value in memory while its run lasts. For an access token that is bounded by its expiry, and for a typed key it isn't
The egress sees a host and a portIt doesn't read what is sent. A declared host that relays, a shared CDN, a paste site, is a way out it can't see. An agent with hosts: any reaches any public address. Bytes aren't limited, only connections
Below the chat's trust, the model's word is enoughA granted function at or below the chat's trust runs with no card, and at trust 3 every granted function does. Trust and grants are security decisions
A refused host is held in memoryA person's refusal of a host, until they next write, lives in the runtime's process. A restart forgets it. Only an input that is itself an address is matched, not one inside a sentence
The code review is a model reading codeIt advises, and it can be fooled. A setting that shows code less often rests on it. Keep always where that matters

Secrets, nodes and the record

LimitWhat it means
A secret passes through the runtime's memoryThe runtime carries a decrypted secret for one call, and holds each open chat's model key. A runtime on someone else's machines is trusted with that. Own nodes only exists for this
Each side of a link must be able to reach the otherThe API server calls a runtime at its address, a runtime calls its sandboxes, and each is called back. A node behind a one-way network doesn't work: every node needs an address the other can reach
A stolen certificate lasts its lifetimeThere is no revocation list. A node's certificate ends within 12 hours, 7 days on one machine, unless the API server refuses it first. A stolen intermediate certifies for up to 120 days
On one's own computer the root isn't offlinedeploy/setup/setup.py keeps the roots in deploy/config/root with their passphrase beside them, and signs an intermediate for 3,650 days. That is fair for a laptop, and it isn't the trust of chapter 12
One database account, in ComposeMONGO_URI carries the database's root account, for the API server and the issuer alike. The issuer needs only a database of its own, and a taken-over issuer reaches more than that
The trail is append-only by codeNothing through the gateway can change a line, and someone holding the database's password could, with nothing to show it. It isn't cryptographically chained
A file's bytes aren't encrypted by the platformIts metadata is. At rest its content is the store's to protect
Content can still carry a secretA password pasted into a message, or one an agent returns as ordinary output, is ordinary data to the platform
It doesn't make the model correctThe model can still choose the wrong customer or write something untrue. The platform keeps the mistake small, visible and, where it matters, waiting for you
A call's outcome can be unknownA job running when a runtime dies is settled as an error, whether or not its work happened. Nothing is retried by itself, and nothing claims it finished
In closing

The model may never be safe. The system around it can be.

Making models resistant to every trick hidden in what they read may never be finished. Deciding what a model's suggestion is allowed to do is a different problem, and that one can be engineered, audited and tested with tools security has trusted for fifty years.

DecentAI is that engineering: permissions that start from no; one gate every call passes; a person's yes for what costs more; one exact release, pinned by digest; agents that hold nothing; strangers' code in jails with one way out; every node proved on every call; results drawn from records, not retyped; a stop that doesn't ask; and a trail that only grows. The model will still be fooled sometimes. When it is, the consequence is small, visible and, where it counts, waiting for you.

The words used here

Agent: a manifest and a program, one exact release of which an organization approved.

Approval: two things. An administrator approving one release, and a person's yes to one call.

Ask: what a running function requests of the runtime.

Card: something in a chat that waits for a person.

Catalog: what a source's address answers.

Contract: what a chat may do right away, answered by the API server.

Digest: sha256: and the hex of a file's bytes. It names a program and proves it.

Egress: the runtime's part that is a run's one way out.

Engine: the API server, runtime, egress, sandbox and issuer together.

Execution node: a runtime and its sandboxes.

Gateway: POST /app, the route every action goes through.

Grant: who may use an agent; a credential lent to one; which functions a chat may call.

Level: 0 to 3, on a function (what it costs) and on a chat (its trust).

Manifest: an agent's contract: what it may do, keep and reach.

Node: a part that holds a certificate and serves on port 8004.

Pass: the token that tells the egress which run is connecting.

Program: the file a run executes, one per machine.

Reference: the id of a stored thing. An approval's, agt_…, is an installed agent's.

Run: one started program, in a jail. There is one per agent per chat.

Scope: the organization a node's certificate says it serves.

Slot: one resource of one installed agent, and the name its things are kept under.

Source: an address agents are installed from.

Step, turn: one model reply and its calls; the steps until a reply that calls nothing.

Trace: what the assistant actually ran in this chat, which evidence is checked against.

Worker: a run, as the worker protocol sees it.
